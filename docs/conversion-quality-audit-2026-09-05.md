# hwpkit 변환 정확도 재점검

2026-09-05, 사용자 갱신 커밋 `887661ce0af118d4cf419cee0d24ff2aca29e610` 기준.
이번 작업 범위는 hwpkit 저장소다. 이전 연구 프로젝트 변경은 다시 덮어쓰지 않았다.

## 지원 형식

HWP(5.x), HWPX, DOCX, Markdown, HTML의 입력과 출력이 등록되어 있다.
5×5 조합 각각 A→B→A 변환 후 제목·한글 본문·표 셀 내용이 남는지 검사했다.
DOC와 PDF는 입력/출력 미지원이며, `.hwpkit`이라는 별도 형식도 없다.
지원 표는 README에 정리했다. DOC 변환기를 새로 구현한 것은 아니다.

기본 왕복 통과는 임의의 실제 문서가 같은 모양으로 보인다는 보증이 아니다.
복잡한 표, 머리말/꼬리말, 수식, 이미지 위치, 페이지 경계는 독립 정답 문서·렌더링 평가가 필요하다.
동일 라이브러리의 인코더와 디코더가 공유하는 오류는 왕복 검사만으로 검출하지 못할 수 있다.

## 최신 코드에서 재현한 문제와 수정

재적용 전 추가 회귀 검사 8개가 실패했다. 기존 테스트는 통과했지만 다음 사례를 검출하지 못했다.

1. ZIP 앞 4 KiB만 보아 word/document.xml이 뒤에 있는 압축 DOCX를 HWPX로 오인했다.
   실제 ZIP 항목을 확인하도록 수정했다. 관계없는 ZIP은 미지원 입력으로 처리한다.
2. 모든 OLE를 HWP로 판단했다. FileHeader의 HWP 서명을 확인하고 WordDocument는 미지원 DOC로 구분한다.
3. 명시 형식의 대문자/선행 점을 지원하지 않았다. `.DOCX`, `HWPX` 등을 정규화한다.
   Blob은 전역 File이 없는 환경에서도 처리하도록 보호했다. 별도 테스트에서 File을 제거하여 확인한다.
4. 문단 스타일 상속 시 자식의 undefined가 부모 값을 덮었다. 정의된 문단 속성만 병합한다.
5. DOCX 들여쓰기의 명시 0 및 음수 여백을 잃었다. 속성 부재와 0을 구분한다.
6. firstLine과 hanging이 함께 있으면 firstLine을 우선했다. hanging 우선으로 수정했다(0 포함).
7. 최신 커밋의 encoder가 본문 여백에 내어쓰기 폭을 더하여 반복 변환마다 위치가 이동했다.
   DocRoot.indentPt는 이미 본문 여백이므로 이를 직접 w:left로 기록한다.
   예: 본문 36pt, 내어쓰기 18pt가 저장/재입력 후 본문 54pt로 변하던 오류를 제거했다.

### 최신 내어쓰기 테스트를 수정한 이유

기존 HangingIndent.test.ts는 left >= hanging을 항상 만족하도록 요구했다.
하지만 Word의 첫 줄 위치는 본문 여백과 첫 줄 들여쓰기로 결정되며,
본문 여백보다 왼쪽에 첫 줄을 배치하는 것 자체가 금지된 것은 아니다.
이를 강제로 막으면 원본 레이아웃이 바뀐다.

테스트를 삭제하지 않고 정확한 본문/첫 줄 좌표를 검사하도록 바꾸었다.
양수 첫 줄 들여쓰기 검사도 유지했다. 별도 테스트는 0/음수 값과 3회 DOCX 왕복의 좌표 안정성을 확인한다.
최신 Markdown 인코더/디코더 구현은 수정하지 않아 최근 기능을 유지했다.
